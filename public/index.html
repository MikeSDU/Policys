THE COMPARISON

What changes between methods?

Rules-based search ranks policies by shared keywords and returns the selected policy text verbatim, so it uses no LLM tokens and cannot invent new wording; however, it can select an irrelevant policy and struggles with paraphrases. The LLM without a vector index receives all 98 policies, which avoids retrieval omissions but sends more policy text in each prompt. The LLM with a vector index uses normalized TF-IDF vectors and cosine similarity to select up to five records before calling the same Gemini model. This is a lexical vector index, not a semantic embedding model. Each run displays wall-clock response time, API-reported input, output, thinking and total tokens, the selected policies and quoted evidence; timings include retrieval and network work, and the two LLM calls run concurrently.

I prefer the vector-index approach as a starting point for a larger policy database because it restricts the supplied context to potentially relevant policies and can reduce prompt token use. This is a design preference, not a measured conclusion about quality or speed: TF-IDF may miss synonyms or retrieve the wrong department, and a full-context model may work better for this small database. Verified quotations prove only that cited text exists, not that the whole answer follows from it. To compare unsupported-answer tendencies, run the same questions across all methods, include paraphrases and questions absent from the database, manually check each claim against the original records, and report the proportion of unsupported answers separately from abstentions. No hallucination rates or performance averages are claimed before that evaluation.
